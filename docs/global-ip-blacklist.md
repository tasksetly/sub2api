# 全站 IP 黑名单

在「系统设置 → 安全与认证 → 全站 IP 黑名单」管理名单，每行输入一个 IPv4、IPv6 地址或 CIDR 网段，然后在此区域单独保存。默认关闭；删除有注册 IP 记录的用户时会自动启用。关闭开关或删除对应规则后保存，即可解除封禁。

支持最多 5000 条规则，保存时自动规范化、去重；CIDR 中的主机位会被清除，例如 `198.51.100.42/24` 保存为 `198.51.100.0/24`。IPv4 映射的 IPv6 地址会按 IPv4 处理。

## 生效范围

- 名单持久化在现有 `settings` 表；新增迁移 `265_user_registration_ips.sql` 保存后续新用户的注册 IP，需随版本部署应用。
- 保存后当前实例立即生效，其他实例通常在 5 秒内重新读取配置。
- 命中后返回 HTTP 403，错误代码 `IP_BLOCKED`。拦截位于应用前端和业务接口之前，包括页面、注册、登录、工单、模型 API、管理接口、健康检查、支付回调及 OPTIONS 请求，没有管理员豁免。
- 规则对后续请求生效；已建立的流式请求或长连接不会被主动断开。
- 由 Nginx、CDN 单独提供或缓存的页面、静态文件不经过应用，需要在对应入口另设规则；到达应用的请求仍受本名单限制。
- 数据库暂时异常或存储配置损坏时保留上次成功读取的名单；进程尚无可用配置时返回 HTTP 503（`IP_BLACKLIST_UNAVAILABLE`），恢复读取后自动继续服务。配置不存在表示默认关闭。
- 缓存过期后只允许一个请求刷新配置，刷新读取最多等待 3 秒。其他请求遇到正在刷新或写入的名单时，立即使用最近有效的名单；没有可用缓存时立即返回 503，不排队等待删除事务。写入提交后才发布新名单，事务期间新增的封禁尚未生效。

## 反向代理

封禁和保存时的防误封检查统一使用 Gin 的可信代理链，配置项为 `server.trusted_proxies`。页面会显示本次请求识别的 IP，启用前应确认它是实际客户端地址。

只将真实代理地址加入可信列表，并由入口代理正确处理转发头。未经配置的代理连接将按直接连接地址识别；不要将所有来源设为可信，也不要向未经清洗的转发头授予信任。

本功能不使用旧版兼容开关直接信任 `CF-Connecting-IP`、`X-Real-IP` 等原始转发头的行为，避免客户端伪造头部绕过封禁。处于 Cloudflare 或多层代理后的站点，需要正确配置整条可信代理链和转发头。

## 防误封与恢复

启用时，如果任一规则覆盖当前操作管理员的 IP，保存会失败（`IP_BLACKLIST_SELF_BLOCK`），包括覆盖该 IP 的 CIDR。共享出口的用户会一起被封禁，保存前会要求确认。

如果管理员之后换了网络而落入已封禁网段，可从其他未封禁的网络登录并修改名单。必要时由数据库管理员执行以下恢复操作（此为操作示例，功能开发不会执行它）：

```sql
UPDATE settings
SET value = '{"enabled":false,"rules":[]}', updated_at = NOW()
WHERE key = 'global_ip_blacklist';
```

各实例通常在 5 秒内读取新配置，不需要重启。若数据库不可用，应先恢复数据库访问。

## 删除用户时自动封禁

用户管理的单个删除和批量删除共用后端删除逻辑：如果用户存在注册 IP 记录，删除用户、删除其 API Key、追加封禁规则在同一个数据库事务中提交；任一操作失败都会回滚，并且不会更新内存名单。多个实例并发删除时通过数据库事务锁合并规则，避免相互覆盖。提交后当前实例立即拦截该 IP，其他实例按上述缓存时间同步。

保存名单及带封禁的删除事务使用 10 秒总超时，包含进程内排队、数据库事务锁等待和事务操作；请求本身有更短期限时使用更短期限。等待这些操作不会阻塞全站请求读取已有名单。

删除会自动启用全站黑名单，包括之前保存但关闭的规则；确认框中会明确说明这一点。已有规则覆盖注册 IP 时不会重复添加。若封禁会覆盖当前操作管理员 IP，或者规则已满且需要新增，整个删除操作会失败，不会只删除用户而漏掉封禁。

旧版本没有保存注册 IP，历史用户和后台创建的用户可能没有记录。这些用户仍可删除，响应与界面会明确提示未自动封禁 IP；不会把最近登录 IP、调用 IP 或当前管理员 IP 当作注册 IP。可在掌握可靠来源后手动加入名单。

新账号仅在公开认证路由创建时记录注册 IP，普通邮箱注册和 OAuth 建号共用持久化逻辑，记录与账号创建处于同一事务；登录、刷新 token、修改用户以及后台创建账号不会覆盖注册 IP。注册 IP 与封禁检查使用同一条可信代理链。

## 管理接口

沿用现有管理员认证与审计：

- `GET /api/v1/admin/settings/global-ip-blacklist`：读取配置及 `version`、`current_ip`、`max_rules`，响应禁止缓存（`Cache-Control: no-store`）。
- `PUT /api/v1/admin/settings/global-ip-blacklist`：整体替换配置；必须显式传入 `enabled`、`rules` 和读取时取得的 `version`，不接受缺失或 `null`，请求体最多 1 MiB。成功响应返回保存后的版本。
- `DELETE /api/v1/admin/users/:id`：删除结果含 `registration_ip_blacklisted`，有记录时还会返回 `registration_ip`；无记录时该布尔值为 `false`。

`version` 是服务端生成的令牌，包含 64 个十六进制字符，应原样携带。缺失或格式错误返回 400。服务端在与自动封禁共用的数据库事务锁内检查版本：若读取后名单已被其他操作修改，返回 HTTP 409（`IP_BLACKLIST_VERSION_CONFLICT`），不会写入。直接修改数据库中的名单也会使内容不同的旧版本失效；无需增加数据库字段。

页面遇到冲突会保留当前编辑内容，显示提示并暂停保存。先复制需要保留的编辑内容，再刷新、核对最新名单并重新编辑后保存；不能直接换上新令牌自动重试旧的整份名单，否则仍会覆盖新封禁。

保存示例（`<GET 返回的 version>` 必须替换为实际读取到的令牌）：

```json
{
  "enabled": true,
  "rules": ["203.0.113.10", "198.51.100.0/24", "2001:db8::/32"],
  "version": "<GET 返回的 version>"
}
```

读取并确认最新名单后，解除全部封禁：

```json
{"enabled": false, "rules": [], "version": "<GET 返回的 version>"}
```
