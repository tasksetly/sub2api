# 这个开源项目的线上服务，为什么采用按量计费

这个开源项目部署成线上服务后，遇到最多的问题不是“有多少模型”，而是“我只偶尔用几次，为什么要再买一个整月订阅”。

这也是 Tasksetly 目前采用余额按量付费的原因：用多少扣多少，至少让账单和实际调用挂在一起。

## 当前规则

- 充值 1 CNY，折算 1 USD 余额；
- Token 消耗从模型基准价格的 0.1 倍起；
- 当前支持 GPT 5.4、GPT 5.6 及以上版本；
- 精确模型名、输入/输出价格和当前可用情况，以控制台显示为准；
- 注册并验证邮箱后，可以提交站内工单申请 3 USD 体验兑换码；
- 体验码由人工发放，工单 24 小时内处理。

这里的“0.1 倍起”不是一句笼统的低价口号。不同模型、输入输出 Token 和缓存计费可能不同，所以最终价格会放在控制台和公开价格说明里，并标注核验时间。

## 3 USD 体验码怎么申请

体验码不是注册后自动到账。流程是：

1. 注册账号；
2. 完成邮箱验证；
3. 进入站内工单；
4. 说明你的使用场景；
5. 等待人工处理并兑换。

这样做的原因很实际：早期服务需要知道用户卡在哪里，也要避免把体验额度发给完全不会使用 API 的账号。体验码本身没有额外的模型、次数或并发限制，但实际调用仍会受当前可用模型和服务状态影响。

## 适合什么人

它更适合：

- 已经在使用 Codex CLI，想先小额验证接入的人；
- 不想为偶尔使用的工具长期支付固定月费的人；
- 需要看调用明细和余额变化的人；
- 想在一个 API Key 下管理开发工具调用的人。

如果你需要企业账单、合同、固定 SLA 或专门客服，当前版本还不是为这个场景准备的。项目先把个人开发者的注册、配置、调用和计费体验跑通，再考虑团队能力。

## 希望用户反馈什么

如果你愿意试，最有帮助的反馈是：

- 从注册到第一次成功调用用了多久；
- 哪个配置步骤最容易误解；
- 用量明细是否能解释扣费；
- 失败时是否知道下一步该查什么。
