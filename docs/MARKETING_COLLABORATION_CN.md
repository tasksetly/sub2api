## 1. 目标与边界

首阶段不以曝光或注册量为目标，而是验证一条可复用链路：**高意图开发者 -> 注册 -> 创建 API Key -> 完成真实调用 -> 首次付费**。

首推对象建议锁定为使用 Codex、Claude Code 或 Gemini CLI 的个人开发者与 2-20 人研发团队。对外只使用能由产品数据、配置或授权证明的价格、模型、试用、可用性和服务表述；不使用“官方”“最低价”“永不宕机”等无法验证的承诺。

- [ ] 试用开放前启用人机验证、邮箱验证、频控和异常账户处置。

### 验证后推进

- [ ] 发布 2 篇高意图教程和 1 条真实接入视频。
- [ ] 邀请 30-50 名目标开发者，优先一对一观察而非泛流量。
- [ ] 与 3-5 位技术创作者或开源项目进行小范围、可归因合作。
- [ ] 灰度测试邀请返利，冻结 7-14 天并人工检查套利与退款。
- [ ] 仅对已带来至少 3 名付费用户且 90 天贡献毛利为正的渠道追加预算。

## 8. 每周看板与停损规则

每周按渠道查看：有效访问、CTA、注册、邮箱验证、创建 Key、首次成功调用、24 小时内 3 次调用、首付费、D7 留存、净收入、上游成本、退款、试用成本和客服工单。

以下任一情况应暂停该渠道并复盘：

- 花费达到两个付费 CAC 上限仍无付费用户。
- 累计 50 个注册后，激活率低于全站平均的 70%。
- 退款、拒付、滥用或客服负担明显高于全站平均。
- 内容或合作方无法提供真实来源，或使用误导性宣传。

推荐计算方式：

```text
90 天贡献毛利 = 90 天净收入 - 上游调用成本 - 支付手续费 - 退款/拒付 - 可变客服成本
付费 CAC 上限 = 90 天贡献毛利 x 35%
```
