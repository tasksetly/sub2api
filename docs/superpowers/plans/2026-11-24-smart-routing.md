# 全平台账号智能路由方案

## 背景与目标

上游账号来源多、状态差异大。当前网关已有分组账号池、粘性会话、优先级、负载与最近使用时间等调度能力，OpenAI 另有专用评分逻辑。希望将定期探测得到的账号表现转为统一的组内权重，让健康、响应快且成本合适的账号获得更高流量，同时保留其他可用账号参与服务和故障回退。

评分与调度默认自动运行，不提供需要管理员开启的总开关。

## 方案

### 自动探测与模型候选

- 后台每 5 分钟刷新账号分数，探测按账号隔离，失败不得中断其他账号的评分。
- 按平台配置有序的探测模型候选列表。账号不支持当前模型时，尝试列表中的下一个候选模型；平台未配置候选时，使用该账号平台的现有默认测试模型。
- 仅在明确的模型不存在或不支持错误时顺延候选。超时、限流、认证错误等作为本次探测失败记录，不因评分探测直接暂停或禁用账号。
- 探测使用项目现有账号测试链路和协议适配，复用账号凭据、模型映射、代理和平台行为，避免另造上游请求实现。
- 探测并发随账号数量动态调整，建议 worker 数为 `ceil(sqrt(账号数))`，至少 1 个，并设置可配置上限以避免突发占满上游和本机资源。探测总量较大时分批提交任务。

### 评分与权重

- 使用滚动窗口内的探测与实际调用信号形成账号评分，至少包含成功率、延迟、负载和上游成本四项构成。
- 新探测结果采用平滑更新，减少单次波动对调度的影响。评分应包含总分、分项、所用模型和更新时间，供调度与管理员排查。
- 支持按分组配置四项指标的相对权重；没有分组自定义配置时使用系统默认值。成本信号缺失时按中性贡献处理，不能因此让账号失去调度资格。
- 分数映射为正的调度权重，在同一分组、同一请求可用账号集合内进行加权随机选择。账号仍须满足现有平台、模型、账号状态、配额、限流、并发和利润准入条件。
- 保留现有账号优先级层级。先应用既有优先级策略，再在当前优先级候选集合中按智能评分加权，避免智能分数静默覆盖管理员已有的优先级设置。
- 粘性会话继续优先复用有效绑定。账号不可调度或请求失败时，沿用现有剔除与重试流程选择下一候选。
- 缺少评分或评分读取失败时沿用当前调度顺序，评分逻辑不得阻断请求。

### 配置与管理展示

- 管理员可配置各平台有序探测模型，以及各分组的评分指标权重。探测模型列表支持多个模型，顺序表达首选与回退关系。
- 账号管理页展示总分、分项、探测模型和更新时间。分数组件复用现有调度分数列，支持按组查看适用分数。
- 配置 API 对未知平台、空模型项、重复模型、负权重、非有限数值及全部权重为零等输入做校验，并提供默认值回退。

## 数据与兼容

- 复用账号现有扩展字段持久化评分快照，明确只写入由系统生成的评分命名空间，不让账号编辑接口接受客户端伪造的评分。
- 为旧账号和旧快照提供缺省处理。发布后评分尚未生成时继续使用现有调度。
- 若评分快照写入账号扩展字段会触发重型快照重建或在调度热路径增加数据库访问，应调整为独立缓存/仓储，并由调度快照读取，避免每次选号查询数据库。
- 系统配置通过现有设置存储和管理员设置 API 管理，增加字段时保留未提交字段，兼容既有设置部分更新语义。

## 验收标准

- 所有已接入平台均能用其配置候选模型探测，明确模型不支持时按顺序回退，其他错误按探测失败处理且不自动修改账号启停状态。
- 探测任务数量增加时并发按配置函数增长并遵守上限，任务取消、单账号错误和多实例运行不会造成任务泄漏或重复评分写入。
- 评分分项变化能按分组配置影响组内选择概率，权重为零的维度不影响结果，缺失信号按默认策略处理。
- 原有优先级、模型过滤、粘性会话、并发槽、配额、限流、利润规则和失败重试均有回归覆盖。
- 评分未生成、缓存不可用或后台评分失败时请求仍能按原有选择逻辑完成。
- 管理端能保存平台模型顺序与分组权重，并展示对应的评分分项及更新时间。

## 尚需在实现前落定

- 成功率与延迟的滚动窗口长度、分数归一化区间及平滑系数。
- 负载和上游成本的统一信号来源及跨平台可比口径。现有 OpenAI 专用评分中的成本信号可作为复用参考。
- worker 并发上限、探测请求超时和是否需要跨实例领导者锁。
- 分组权重与平台模型配置在管理端设置页的具体表单布局。
